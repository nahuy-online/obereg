# ADR-0006: Версионирование публичного API ядра

- Статус: принято
- Дата: 2026-09-22
- Контекст: [interfaces.md](../interfaces.md) §10, [module-registry.json](../module-registry.json), ADR-0004

## Контекст

Публичное API ядра потребляют три внешних контракта: C ABI (`obereg-ffi`), JNI (`obereg-jni`) и Rust-крейт (`obereg-core`). Оболочки и CLI обновляются независимо от бинарника ядра. Нужны единая точка истины по версии, классификация ломающих изменений и процесс релиза, не дающий сломать собранные оболочки.

## Решение

1. **SEMVER** по `CORE_API_MAJOR.MINOR.PATCH`; текущая версия `CORE_API_VERSION = "0.1.0"`, `CORE_API_MAJOR = 0`.
2. Версия задаётся **в коде** (`obereg-core::version`) и дублируется ровно в двух местах: `docs/module-registry.json` (`core_api_version`) и JSON-статусе сессии (`obereg_core_status`/`statusJson`). Расхождение — дефект, ловится CI-тестом контракта.
3. При `MAJOR = 0`: **ломающее** изменение → bump `MINOR`; **не ломающее** → bump `PATCH`.
4. Классификация изменений — таблица в §10 [interfaces.md](../interfaces.md); спорные случаи решаются в пользу «ломающего».
5. FFI-слой **обязателен к обратной совместимости в пределах `MAJOR = 0`**: собранная оболочка со старым контрактом работает поверх обновлённого `libobereg.so`/`libobereg.a` (существующие символы не меняют сигнатуру, коды ошибок не переиспользуются).

## Процесс изменения API

| Шаг | Действие | Проверка |
|---|---|---|
| 1 | Изменение в коде + правка `interfaces.md` | дифф сводится к таблице §10 |
| 2 | Тест на контракт: символы C ABI vs `module-registry.json`, JSON-статус vs `CORE_API_VERSION` | CI зелёный |
| 3 | Запись в `changelog.md` (в корне репозитория): категория `Added/Changed/Removed/Fixed`, пометка breaking | ревьюер сверяет bump |
| 4 | Bump `CORE_API_VERSION` | три места совпадают |

Правило ревью: любое изменение в `obereg-core` публичной поверхности, `obereg-ffi` или `obereg-jni` обязано ссылаться на строку таблицы §10 — иначе оно считается ломающим по умолчанию.

## Классификация (сводка; полная — в interfaces.md §10)

- **Ломающие** (bump `MINOR`): смена сигнатуры/семантики, удаление/переименование, добавление варианта в `ConnectionState`/`JournalKind`/`CoreError`, добавление обязательного поля сериализуемой структуры, новая функция трейта без `default`.
- **Не ломающие** (bump `PATCH`): опциональное поле с дефолтом, `default`-методы трейтов, новые ключи внутри `fields` журнала, исправления дефектов без изменения контракта.

## Граничные случаи (решения)

- JSON-обмен (статус, журнал, конфиг) выводит эволюцию данных из-под ABI: новые строки-значения enum в JSON считаются ломающими для парсеров, даже если сигнатура Rust не менялась.
- `deny_unknown_fields` в конфиге: любое новое поле конфига обязательно вводится опциональным с `#[serde(default)]`, иначе старые конфиги перестают парситься.
- Изменение кодов возврата C ABI (§2 interfaces.md) — ломающее: коды закреплены, новые ошибки получают новые коды.
- Удаление «устаревшего» (`#[deprecated]`) публичного элемента — по-прежнему ломающее: deprecated ≠ removed.

## Последствия

- Плюсы: один источник версии в коде, предсказуемое обновление оболочек, явный процесс релиза.
- Минусы: любое добавление enum-варианта требует выпуска оболочек одновременно с ядром — осознанная цена стабильности FFI.
